# Alias Implementation Guide

## Overview

The application now uses **aliases** instead of UUIDs in all public-facing API responses. This improves security by hiding internal database IDs and makes URLs more user-friendly.

## How It Works

### 1. Database Aliases
- Aliases are automatically generated from entity names
- Format: `name-to-alias` (lowercase, hyphens, alphanumeric only)
- Unique per entity type (canteens are globally unique, items unique per canteen)
- Auto-generated by database triggers

### 2. API Responses
- All API responses **exclude** the `id` field
- All API responses **include** the `alias` field
- Aliases are used in URLs and public references

### 3. API Requests
- API endpoints accept both **UUIDs** (for backward compatibility) and **aliases** (preferred)
- The system automatically resolves aliases to IDs for database queries

## Alias Format

### Examples:
- Canteen: "South Campus Canteen" → `south-campus-canteen`
- Item: "Chicken Biryani" → `south-campus-canteen-chicken-biryani-abc123`
- Template: "My Usual Order" → `south-campus-canteen-my-usual-order-xyz789`

## API Routes Updated

### Templates API
- `GET /api/templates?canteen_id={uuid|alias}` - List templates
- `GET /api/templates/{alias|uuid}` - Get template
- `POST /api/templates` - Create template (returns alias)
- `PUT /api/templates/{alias|uuid}` - Update template
- `DELETE /api/templates/{alias|uuid}` - Delete template

**Response Format:**
```json
{
  "success": true,
  "data": {
    "alias": "south-campus-canteen-my-usual-order",
    "name": "My Usual Order",
    "description": "...",
    "items": [...],
    // NO "id" field exposed
  }
}
```

## Using Aliases in Frontend

### Before (with UUIDs):
```typescript
// ❌ Exposed UUID
const templateId = "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
router.push(`/templates/${templateId}`)
```

### After (with aliases):
```typescript
// ✅ User-friendly alias
const templateAlias = "my-usual-order"
router.push(`/templates/${templateAlias}`)
```

## Backward Compatibility

The system maintains backward compatibility:
- **Accept**: Both UUIDs and aliases in API requests
- **Return**: Only aliases in responses (no UUIDs exposed)
- **Internal**: Still uses UUIDs for database operations

## Security Benefits

1. **No ID Enumeration**: Attackers can't enumerate IDs
2. **Better URLs**: `/templates/my-usual-order` vs `/templates/uuid`
3. **Privacy**: Internal database structure not exposed
4. **SEO Friendly**: Aliases are readable and shareable
